# Перенос сайта на домен и хостинг

Всё, что нужно залить на сервер, лежит в папке **`dist/`** — это готовый сайт: HTML,
стили, шрифты, картинки, обработчик заявок и настройки сервера. Ничего компилировать
на хостинге не нужно.

```
dist/
├── index.html, proekty.html, obekty.html …   10 страниц
├── assets/           стили, шрифты, скрипты, изображения
├── api/              приём заявок (PHP)
├── .htaccess         https, редиректы, кеш, сжатие  ← не потеряйте, файл скрытый!
├── favicon.ico, apple-touch-icon.png, icon-192.png, icon-512.png
├── site.webmanifest, robots.txt, sitemap.xml
└── 404.html
```

Обновить сборку: `npm install` (один раз) → `npm run build`.
Собрать архив для загрузки через панель хостинга: `npm run pack` → `karkascomfort-site.zip`.

---

## 1. Перед началом: сохраните текущий сайт

1. В панели хостинга сделайте **резервную копию** папки сайта и базы данных.
2. Выгрузите себе копию по FTP — это план отката, если что-то пойдёт не так.
3. Выпишите список текущих адресов страниц (Яндекс.Вебмастер → «Страницы в поиске»).
   Он понадобится в пункте 6, чтобы не потерять позиции.

---

## 2. Загрузка файлов

Выберите любой из трёх способов — результат одинаковый.

### Способ А. Панель хостинга (проще всего)

1. `npm run pack` → получится `karkascomfort-site.zip`.
2. Файловый менеджер хостинга → откройте папку сайта (`public_html`, `www` или `htdocs`).
3. Удалите или переименуйте старые файлы (после того как сделали бэкап).
4. Загрузите архив и распакуйте **в корень** папки сайта.
5. Убедитесь, что `index.html` лежит именно в корне, а не в подпапке `dist`.
6. Включите показ скрытых файлов и проверьте, что `.htaccess` на месте.

### Способ Б. FileZilla

1. Подключитесь к хостингу по FTP.
2. В настройках FileZilla включите **Сервер → Принудительно показывать скрытые файлы**,
   иначе `.htaccess` не загрузится.
3. Перетащите **содержимое** папки `dist` (не саму папку) в `public_html`.

### Способ В. Одна команда из проекта

```bash
cp .env.example .env      # один раз: впишите доступы к FTP
npm run deploy            # сборка + выгрузка
npm run deploy -- --dry   # проверить список файлов, ничего не загружая
```

Файл `.env` в репозиторий не попадает — пароли остаются только у вас.

Если удобно запускать выгрузку из GitHub: Actions → **Deploy site** → Run workflow.
Секреты `FTP_HOST`, `FTP_USER`, `FTP_PASSWORD`, `FTP_REMOTE_DIR` добавляются в
Settings → Secrets and variables → Actions.

## 3. Домен и SSL

1. В панели хостинга привяжите домен `karkascomfort.ru` к папке с сайтом.
2. Проверьте A-запись домена: она должна указывать на IP хостинга.
   Записи меняются до 24 часов, обычно быстрее.
3. Выпустите бесплатный сертификат Let's Encrypt (в панели — «SSL» или «Безопасность»).
4. Включите автопродление сертификата.
5. Перенаправление на https и склейку `www` → без `www` уже делает `.htaccess`,
   отдельно в панели включать не нужно (иначе может получиться цикл редиректов).

Если основным адресом должен быть **с www** — в `.htaccess` закомментируйте первый
блок пункта 2 и раскомментируйте второй, затем перезалейте файл.

**На nginx** (VPS вместо обычного хостинга) вместо `.htaccess` используйте
`server/nginx.conf.example` — там те же правила.

## 4. Заявки с форм

Формы отправляют данные в `api/lead.php`. Он проверяет заполнение, отсекает ботов,
шлёт письмо и дублирует заявку в файл `api/leads.csv`.

1. Убедитесь, что хостинг поддерживает **PHP 7.4 и выше** (почти все поддерживают).
2. Откройте `api/config.php` прямо на хостинге и укажите:
   - `to` — почта, куда приходят заявки;
   - `from` — адрес отправителя **на вашем домене**, например `site@karkascomfort.ru`.
     Создайте такой почтовый ящик в панели хостинга: письма с чужого домена
     Яндекс и Mail.ru отправляют в спам.
3. По желанию впишите `telegram_token` и `telegram_chat_id` — заявки будут дублироваться
   в Telegram (токен у @BotFather, ваш chat_id у @userinfobot).
4. Проверьте: отправьте тестовую заявку с сайта и посмотрите почту, папку «Спам»
   и файл `api/leads.csv`.
5. Для надёжной доставки добавьте в DNS домена записи **SPF** и **DKIM** — их значения
   даёт хостинг в разделе «Почта».

Если PHP на хостинге нет — оставьте формы как есть (они покажут подтверждение) и
подключите внешний сервис приёма заявок, поменяв один атрибут в `src/partials/head.html`:
`data-lead-endpoint` в теге `<body>` (задаётся в `tools/build.mjs`, константа `LEAD_ENDPOINT`).

## 5. Проверка после публикации

- [ ] `https://karkascomfort.ru` открывается, замок в адресной строке зелёный
- [ ] `http://karkascomfort.ru` и `https://www.karkascomfort.ru` перекидывают на основной адрес
- [ ] Открываются все 10 страниц, работает меню на телефоне
- [ ] Каталог фильтруется, страница проекта открывается по ссылке из каталога
- [ ] Калькулятор считает, форма отправляется и письмо приходит
- [ ] Несуществующий адрес (`/test123`) показывает страницу 404, а не ошибку сервера
- [ ] Старые адреса (`/karkasnye-doma/`, `/proekty/`) перекидывают на новые страницы
- [ ] Логотип в закладке браузера — иконка компании
- [ ] Ctrl+F5: стили не «слетают» (у файлов в адресе есть `?v=…`)
- [ ] Скорость: PageSpeed Insights, ориентир — 90+ на мобильных

## 6. Чтобы не потерять позиции в поиске

1. **Редиректы.** В `.htaccess` уже прописаны переходы со старых адресов
   (`/karkasnye-doma/`, `/proekty/`, `/kontakty/` и др.). Сверьте список со своими
   реальными адресами из Вебмастера и допишите недостающие по образцу:
   `RewriteRule ^старый-адрес/?$ /новая-страница.html [R=301,L]`
2. **Яндекс.Вебмастер:** «Переобход страниц» → добавьте главную и основные разделы;
   в «Файлы Sitemap» укажите `https://karkascomfort.ru/sitemap.xml`.
3. **Google Search Console:** то же самое — sitemap и запрос на индексирование.
4. **Счётчики.** Код Яндекс.Метрики вставьте в `src/partials/head.html` перед `</head>`
   и пересоберите (`npm run build`). Не забудьте включить «Вебвизор» и цели на отправку формы.
5. Первые две недели следите в Вебмастере за ошибками сканирования.

## 7. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| Ошибка 500 сразу после загрузки | Хостинг не разрешает часть директив `.htaccess`. Закомментируйте в нём строку `Options -Indexes`, затем блок `<IfModule mod_authz_core.c>` в конце файла. Проверяйте после каждого шага. |
| Бесконечный редирект | Перенаправление на https включено и в `.htaccess`, и в панели хостинга. Оставьте что-то одно. |
| Сайт открылся, но без стилей | Папка `assets` не загрузилась целиком либо лежит не в корне. Проверьте, что путь `/assets/css/style.css` открывается в браузере. |
| Открывается старый дизайн | Кеш браузера или CDN хостинга. Ctrl+F5, при наличии CDN — сбросить кеш в панели. |
| `.htaccess` не видно в FileZilla | Включите показ скрытых файлов: Сервер → Принудительно показывать скрытые файлы. |
| Заявки не приходят на почту | Адрес в `from` не на вашем домене, нет SPF/DKIM, либо на хостинге отключена функция `mail()`. Заявки в любом случае пишутся в `api/leads.csv` — проверьте файл. |
| Страница 404 отдаёт стандартную ошибку хостинга | В корне нет `404.html` или панель хостинга переопределяет `ErrorDocument`. |
| Кириллица в CSV превращается в кракозябры | Открывайте файл в Excel через «Данные → Из текста», кодировка UTF-8, разделитель — точка с запятой. |

## 8. Как обновлять сайт дальше

1. Правите содержимое в `src/pages/*.html`, общие блоки — в `src/partials/`,
   каталог — в `src/data/projects.json`, объекты — в `src/data/cases.json`.
2. `npm run build` — пересобрать `dist`.
3. `npm run serve` — посмотреть локально на http://localhost:8080.
4. `npm run deploy` — выгрузить на хостинг.

Файлы в `dist/` править руками не нужно: при следующей сборке они перезапишутся.
