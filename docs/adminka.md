# Админка: заявки, настройки и содержимое сайта

Адрес: **каркаскомфорт.рф/admin/**. Работает только на боевом сервере:
на демо-версии нет PHP, поэтому админки там нет.

У каждого свой логин и пароль. Роли две:

- **владелец** — всё: заявки, содержимое, настройки приёма заявок, пользователи;
- **редактор** — заявки и содержимое сайта.

---

## 1. Первый вход

Первая учётная запись заведена заранее и приезжает вместе с сайтом —
к серверу обращаться не нужно. Логин и пароль переданы отдельно,
в переписке; роль — владелец. При первом открытии админки список
переносится в `api/admin-users.json` на сервере, и дальше всё живёт
только там.

**Первым делом смените пароль** в разделе «Пользователи»: в репозитории
лежит хеш выданного пароля, а репозиторий открытый. После смены скажите
мне — уберу файл-зародыш `api/users.seed.json` из репозитория совсем.

Остальных сотрудников добавляйте там же, каждому свой логин и роль.

**Если учётных записей не осталось вовсе** (файл-зародыш убран, а список
на сервере стёрт), админка попросит код установки — он лежит файлом
на сервере:

```bash
cat /var/www/xn--80aa2abbmnbmggrx.xn--p1ai/public/api/admin-setup.code
```

Пароль подбирать бесполезно: после пяти неудачных попыток вход для этой
пары «логин и адрес» запирается на четверть часа.

---

## 2. Заявки

Всё, что приходит с форм сайта, падает сюда — даже если почта или
Telegram в этот момент не работают.

- статусы: новая, в работе, встреча, договор, отказ;
- заметка к заявке: о чём договорились (видно, кто её оставил);
- поиск по имени, телефону, проекту и заметке;
- выгрузка в CSV для Excel.

Заявки, пришедшие до появления админки, подхватываются из старого
файла `api/leads.csv` — история не теряется.

---

## 3. Настройки заявок

Раздел для владельца. Здесь задаётся, **куда уходит заявка**:

- **почта** — один или несколько адресов через запятую;
- **Telegram** — токен бота от @BotFather и идентификатор чата
  (для группы он начинается с `-100`);
- **CRM** — адрес входящего вебхука и формат: JSON (большинство сервисов,
  Make, n8n) или обычная форма (вебхуки amoCRM и Битрикс24);
- сколько заявок принимать с одного адреса за час.

Кнопка «Отправить тестовую заявку» прогоняет проверку тем же кодом, что
работает на сайте: сразу видно, дошло письмо или нет.

Настройки хранятся в `api/settings.json` на сервере. Выгрузка сайта их
не трогает, в репозиторий они не попадают — токены и почта остаются
только на сервере.

---

## 4. Содержимое сайта

Правки отсюда **не пишутся на сервер напрямую**. Админка сохраняет их
коммитом в репозиторий, дальше срабатывает обычная цепочка: сборка
прогоняет проверки и выкладывает сайт. Поэтому:

- правка появляется на сайте через одну-две минуты;
- у каждой правки есть автор и время, любую можно откатить;
- сайт никогда не расходится с исходниками.

Сейчас правятся: ставки за м² и сроки строительства, названия, площади,
цены и описания проектов каталога, названия, адреса и описания
построенных объектов, подписи к видео. Состояние последней сборки видно
вверху страницы со ссылкой на журнал.

**Что нужно один раз.** Владелец задаёт токен GitHub:
Settings → Developer settings → Personal access tokens → Fine-grained
tokens; доступ — только к этому репозиторию и только `Contents: Read and
write`. Токен хранится на сервере в `api/settings.json`.

Фотографии и видео пока добавляю я: пришлите архив и скажите, к какому
объекту и в какую группу.

---

## 5. Что лежит на сервере

Всё состояние админки — в папке `api/` рядом с сайтом. Ни один из этих
файлов не отдаётся наружу (закрыто и в nginx, и в `.htaccess`) и ни один
не перезаписывается выгрузкой:

| Файл | Что внутри |
|---|---|
| `admin-users.json` | логины, имена, роли и хеши паролей |
| `settings.json` | куда уходят заявки, токен GitHub |
| `leads.jsonl` | заявки |
| `leads-state.json` | статусы и заметки по заявкам |
| `leads.csv` | те же заявки в виде таблицы (страховка) |

Пароли хранятся только хешем. В репозитории нет ни паролей, ни токенов.

---

## 6. Если админка не открывается

На сервере нужно один раз разрешить её в конфигурации nginx — правило
уже есть в шаблоне репозитория, его нужно накатить (от root):

```bash
bash /путь/к/репозиторию/server/nginx-apply.sh
```

Или, если репозитория на сервере нет, скачать шаблон и применить его
тем же скриптом. Выгрузка сайта конфигурацию nginx не трогает, поэтому
шаг делается руками и только один раз.

На обычном хостинге (Apache) ничего делать не нужно: правила уже лежат
в `.htaccess`, который приезжает вместе с сайтом.
