# Каркас Комфорт — сайт компании

Статический сайт (HTML + CSS + JS, без фреймворков). Сборка кладёт готовый сайт
в папку `dist/` — её содержимое и заливается на хостинг.

Дизайн: «Дом в кадре» — тёплая угольно-песочная база, хвойный акцент, антиква Playfair Display
в заголовках и Manrope в тексте. Первый экран — фотография объекта, поверх неё цена, срок и гарантия.

**Перенос на домен и хостинг — в [DEPLOY.md](DEPLOY.md).**

## Быстрый старт

```bash
npm install       # один раз
npm run build     # собрать сайт в папку dist/
npm run serve     # посмотреть локально: http://localhost:8080
npm run check     # прогнать проверки в браузере (нужен npx playwright install chromium)
npm run pack      # архив для загрузки через панель хостинга
npm run deploy    # сборка + выгрузка по FTP (доступы в .env)
npm run fonts     # пересобрать шрифты из tools/fonts-src (нужен python3 + fonttools)
```

Node.js нужен только для сборки. На хостинг уезжает содержимое `dist/` — обычная
статика плюс один PHP-файл для приёма заявок.

## Структура

```
dist/                    ← результат сборки: это и заливаем на хостинг
  proekty/<код>.html     ← страница каждого проекта, генерируется из данных
assets/
  css/style.css          ← вся вёрстка и дизайн-токены
  fonts/*.woff2          ← Playfair Display и Manrope: по одному файлу на семейство
  js/main.js             ← меню, фильтры каталога, квиз, слои стены, формы, аналитика
  img/hero.svg           ← кадр первого экрана
  img/projects/*.svg     ← иллюстрации каталога (заглушки под реальные фото)
  img/photos/            ← сюда кладутся фотографии объектов (см. src/data/README.md)
src/
  partials/              ← общие head, шапка, подвал, блок заявки, панель действий
  pages/                 ← содержимое страниц (правим здесь!)
  data/projects.json     ← каталог проектов: площадь, цена, фотографии
  data/cases.json        ← построенные объекты для блока портфолио
  data/pricing.json      ← ставки за м², из них считаются цены и квиз
  data/reviews.json      ← отзывы: пока пусто, блок на сайте не выводится
  data/site.json         ← номера счётчиков аналитики и контакты мессенджеров
  data/README.md         ← что и как заполнять в данных
server/
  .htaccess              ← настройки Apache: https, редиректы, кеш, сжатие
  nginx.conf.example     ← то же самое для nginx
  api/lead.php           ← приём заявок: почта, Telegram, CRM, запасная запись в CSV
  api/config.php         ← куда слать заявки и доступы к интеграциям (правится на хостинге)
tools/
  build.mjs              ← сборка страниц, страниц проектов и sitemap.xml
  gen-art.mjs            ← генерация иллюстраций
  gen-fonts.mjs          ← сборка шрифтов из tools/fonts-src
  gen-icons.mjs          ← favicon и иконки для телефонов
  check.mjs              ← проверки собранного сайта в браузере
  deploy-ftp.mjs         ← выгрузка dist на хостинг
```

**Страницы проектов не редактируются руками:** файл `dist/proekty/<код>.html` собирается
из `src/data/projects.json`. Чтобы изменить цену, фото или описание — правьте данные.

**Важно:** папка `dist/` перезаписывается при каждой сборке. Правьте `src/pages/*.html`,
`src/partials/*.html` и данные в `src/data/`, затем запускайте `npm run build`.

## 1. Фирменные цвета

Палитра — в одном блоке в начале `assets/css/style.css`:

```css
:root {
  --brand:      #2F5D3F;   /* хвойный зелёный: кнопки, ссылки */
  --brand-deep: #1E3D29;   /* тёмные поверхности: блок заявки */
  --accent:     #8A5E2B;   /* тёплое дерево для текста (проходит контраст AA) */
  --accent-bright: #C08A4A;/* то же дерево для плашек и крупных элементов */
  --ink:        #17150F;   /* основной текст и тёмные секции */
  --page:       #F4EFE7;   /* песочный фон страницы */
  --page-2:     #EDE6DA;   /* второй тон для чередования секций */
  ...
}
```

Меняя цвета, проверяйте контраст: мелкий текст должен давать не меньше 4.5 к фону,
крупный — 3. Именно на этом сайт спотыкался до редизайна.

Замените значения на фирменные — они применятся ко всем страницам. Ниже в файле
такой же блок для тёмной темы (`prefers-color-scheme: dark`); если она не нужна,
блок можно удалить целиком.

Цвета иллюстраций задаются отдельно — объект `C` в `tools/gen-art.mjs`
(после правки `npm run build`).

## 2. Шрифты

Playfair Display (заголовки) и Manrope (текст) лежат в `assets/fonts` — по одному файлу
на семейство, без обращения к Google Fonts. Каждый файл содержит и кириллицу, и латиницу,
и знаки вроде «м²», «×», «₽»: раньше из-за них браузер тянул второй файл на семейство.

Пересобрать шрифты (нужен `python3` с `fonttools` и `brotli`):

```bash
pip install fonttools brotli
npm run fonts       # берёт переменные шрифты из tools/fonts-src и урезает до нужных знаков
```

Знака рубля в Playfair Display нет вовсе, поэтому в `--display` сразу за ним стоит Manrope —
цены набираются им, а не системным шрифтом. Чтобы сменить шрифт: положите переменный `.ttf`
в `tools/fonts-src`, поправьте список в `tools/gen-fonts.mjs`, затем `@font-face`
и переменные `--display` / `--text` в начале `style.css`.

## 3. Реальные фотографии вместо иллюстраций

Иллюстрации — временные заглушки. Чтобы поставить настоящие фотографии, код править
не нужно — только данные:

1. Положите файлы в `assets/img/photos/` (рекомендуемый размер 1600×1067, пропорции 3:2).
2. В `src/data/projects.json` у нужного проекта перечислите их в поле `photos`,
   например `"photos": ["kd-29-fasad.webp", "kd-29-interier.webp"]`. Первый кадр
   становится главным на карточке и попадает в превью для мессенджеров.
3. Планировку укажите в поле `plan`.
4. То же самое для построенных объектов — `src/data/cases.json`.
5. Кадр первого экрана — `assets/img/hero.svg`; замените на широкое фото (2400×1350)
   и поправьте `src` в `src/pages/index.html`.

После правки данных: `npm run build`.

## 4. Каталог, цены и портфолио

`src/data/projects.json` — каталог, `src/data/cases.json` — построенные объекты,
`src/data/pricing.json` — ставки за квадратный метр. Подробности по каждому полю —
в `src/data/README.md`.

**Цены сейчас считаются формулой** «площадь × базовая ставка» и подписаны как
ориентировочные. Как только появится реальный прайс, проставьте `price` у каждого
проекта — подпись автоматически сменится на «под ключ, по договору», а расчёт
перестанет быть приблизительным. Ставки для квиза меняются в `pricing.json`
в одном месте — код трогать не нужно.

**Отзывы** берутся из `src/data/reviews.json`. Пока массив пуст, блок отзывов
на сайте не выводится вовсе: выдуманные отзывы с сайта сняты, ждём настоящие
с указанием источника.

## 5. Заявки: почта, Telegram, CRM

Форма отправляет JSON `{ name, phone, message, project, consent, page }` на
`/api/lead.php`. Адрес задаётся при сборке и лежит в атрибуте `<body data-lead-endpoint>`;
в демо-версии он пуст — там формы работают вхолостую.

Куда уходит заявка, настраивается на хостинге в `api/config.php`, пересобирать сайт
не нужно:

| Параметр | Зачем |
|---|---|
| `to`, `from`, `subject` | письмо менеджеру |
| `telegram_token`, `telegram_chat_id` | дубль в Telegram: токен у @BotFather, chat_id у @userinfobot (для группы — id вида `-100…`) |
| `crm_webhook`, `crm_format`, `crm_fields` | заявка в CRM: адрес входящего вебхука, формат (`json` или `form`) и соответствие полей |
| `log_file` | запасная запись всех заявок в CSV рядом со скриптом |
| `rate_limit` | сколько заявок с одного IP принимаем за час |

Заявка пишется в CSV всегда — даже если почта и интеграции недоступны. Если ни один
канал не принял заявку, посетитель видит честное сообщение с телефоном, а не ложное
«спасибо». Файл `leads.csv` и `config.php` закрыты от посторонних в `.htaccess`
и в примере конфигурации nginx — при переносе на другой веб-сервер это нужно повторить.

## 6. Аналитика

Номера счётчиков — в `src/data/site.json`. Пустая строка означает, что счётчик
не подключён и его код на сайт не попадает:

```json
{ "metrika": "12345678", "gtag": "", "whatsapp": "79201716969" }
```

Сайт сам отправляет события: `lead_sent` (отправлена заявка), `lead_error`,
`quiz_step` (шаг квиза), `call_click` (клик по телефону), `messenger_click`.
В Яндекс.Метрике их достаточно завести как цели с теми же именами.

- [ ] Карточки объектов в `cases.json` — сейчас это заготовки
- [ ] Политика конфиденциальности — согласовать с юристом

- [ ] Доступы для Telegram и CRM в `api/config.php` на хостинге

## Проверено

Автотесты в headless Chromium (`npm run check`, 41 проверка): каталог отдаётся
готовой разметкой и фильтруется без перерисовки, фильтр сохраняется в адресе,
страницы проектов существуют отдельными адресами с разметкой Product + Offer
и собственными canonical, старый адрес `proekt.html?id=` не индексируется,
квиз считает вилку и переключает шаги, формы объявляют ошибки ассистивным
технологиям, маска телефона, мобильное меню (блокировка фона, Escape),
отсутствие горизонтальной прокрутки на 390 px, цена и срок видны на первом экране,
панель действий не перекрывает контент, доступность всех внутренних ссылок,
sitemap со страницами проектов, загрузка шрифтов одним файлом на семейство,
а также реальная отправка заявки на PHP-обработчик (валидация, отказ без согласия,
ловушка для ботов, ответ 405 на GET, обезвреживание формул в CSV).
